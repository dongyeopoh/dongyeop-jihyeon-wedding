# 작업 노트: 모르면 빠지는 함정과 비직관적인 동작

## 배포 명령이 푸시 단계에서 거부된다

- 증상: `npm run deploy` 가 마지막 푸시에서 `non-fast-forward` 로 멈춘다.
- 원인: 원격 `gh-pages` 가 이 컴퓨터가 마지막으로 가져온 것보다 앞서 있다(다른 컴퓨터에서 먼저 배포했거나 GitHub 에서 직접 건드린 경우). 스냅샷 커밋은 "가져온 시점의 원격 최신"을 부모로 만들어지므로 그 사이 원격이 움직이면 거부된다.
- 대응: `npm run deploy` 를 그냥 다시 실행한다(새로 가져온 최신을 부모로 다시 만든다). 강제 푸시로 해결하지 않는다. 확인: 1~2분 뒤 스크립트가 출력한 `curl` 명령이 "반영됨" 을 출력한다.

## 지도 자리에 "지도를 불러오지 못했습니다" 가 뜬다

- 증상: 오시는 길 섹션의 지도 자리에 안내 문구 상자만 보인다(길찾기 버튼과 약도는 정상).
- 원인 두 가지. (1) `.env` 의 `VITE_NAVERMAPS_KEY_ID` 값이 네이버 콘솔의 Key ID 와 다르다(키가 아예 없으면 빌드 자체가 멈추므로, 뜬다면 값이 틀린 것이다). (2) 접속한 주소가 네이버 콘솔의 Web 서비스 URL 에 등록되어 있지 않다. 개발 서버 `http://localhost:5173`, 배포 전 미리보기 `http://localhost:4173`, 운영 `https://dongyeopoh.github.io` 가 각각 등록되어 있어야 한다. 휴대폰에서 LAN 주소로 열면 미등록이라 이 안내가 뜨는 것이 정상이다. 네이버는 인증 실패를 스크립트 로드 **뒤에** `window.navermap_authFailure` 로 알려 주므로, `Map.jsx` 는 이미 만든 지도를 지우고 안내 상자로 바꾼다.
- 대응: 콘솔의 Key ID 와 `.env` 값을 대조하고 다시 빌드하거나, 콘솔에 접속 주소를 등록한다. 확인: `grep -c "ncpKeyId=$(grep '^VITE_NAVERMAPS_KEY_ID=' .env | cut -d= -f2- | tr -d '\"')" dist/assets/index-*.js` 가 1 이어야 번들에 키가 들어간 것이다.

## 지도 스크립트는 한 번만 끼워 넣는다

- 증상: 개발 모드에서 지도가 두 개 겹치거나, 한 번 실패한 뒤 다시 시도되지 않는다.
- 원인: React 개발 모드의 StrictMode 가 effect 를 두 번 실행한다. `Map.jsx` 는 같은 주소의 `<script>` 가 문서에 이미 있으면 다시 넣지 않고 그 로드 완료만 기다리며, 첫 effect 의 cleanup 이 취소 플래그를 세워 늦게 오는 콜백을 무시한다. 네트워크 오류로 한 번 실패한 `<script>` 는 문서에 남아 재시도되지 않는데, 현재 페이지 구조에서는 Map 이 다시 마운트되는 일이 없어 문제가 되지 않는다.
- 대응: 이 중복 방지와 취소 플래그를 지우지 않는다. 재시도가 필요해지면 실패한 태그를 제거한 뒤 다시 넣는 로직을 추가해야 한다. 확인: 개발 서버에서 `document.querySelectorAll('script[src*="maps.js"]').length` 가 1 이다.

## 날짜가 세 곳에 따로 있다

- 증상: 화면의 달력은 11월인데 공유 미리보기나 인사말에는 다른 날짜가 보인다.
- 원인: 예식 일시가 `src/data.json` (문구), `src/layout/Calendar/Calendar.jsx` (계산용 `Date` 와 표시할 달), `index.html` (메타 태그) 세 곳에 각각 적혀 있고 서로를 참조하지 않는다.
- 대응: 날짜를 바꾸면 세 파일을 모두 고친다. 확인: `grep -rn "2024" src/data.json src/layout/Calendar/Calendar.jsx index.html` 로 남은 옛 날짜가 없는지 본다.

## 방명록이 두 번 뜨거나 안 뜬다

- 증상: 개발 서버에서 방명록 영역이 두 개 생기거나, 배포 후 빈 칸이다.
- 원인: 개발 모드의 `StrictMode` 는 effect 를 두 번 실행한다. `Comment.jsx` 는 같은 스크립트 태그가 이미 있는지 검사해서 두 번째 삽입을 막고 있으므로, 이 검사를 지우면 두 개가 생긴다. 배포 후 빈 칸은 utterances GitHub 앱이 저장소에서 빠졌거나 저장소가 비공개가 된 경우다.
- 대응: 중복 검사 로직을 유지한다. 빈 칸이면 GitHub 의 저장소 설정 → Integrations 에서 utterances 가 설치되어 있는지, 저장소가 Public 인지 확인한다. 방명록 글은 제목이 `/dongyeop-jihyeon-wedding/` 인 이슈에 쌓이므로 그 이슈를 닫거나 잠그면 새 글이 막힌다.

## 갤러리가 무겁다

- 증상: 휴대폰 데이터로 처음 열면 갤러리 사진이 한참 뒤에 나타난다.
- 원인: 썸네일 전용 파일이 없다. 26장 모두 원본(장당 0.2~3.0MB, 합계 약 59MB; 다섯 장은 긴 변 4032px 의 촬영 원본)이 썸네일로도 쓰이고 라이트박스 원본으로도 쓰인다. 접힌 상태(60vh)라도 `img` 태그는 전부 렌더되므로 26장을 다 받는다.
- 대응: 사진을 추가할 때는 긴 변 1920px 이하로 줄여서 넣는다(대부분의 기존 사진이 1280×1920 이라 화면에서 차이가 없다). 확인: `du -sh src/assets/images` 가 추가 후에도 크게 늘지 않아야 한다.

## 공유 미리보기 사진이 옛것으로 보인다

- 증상: 카카오톡에 링크를 붙이면 사진이 안 나오거나 바뀌기 전 미리보기가 보인다.
- 원인: 메신저가 링크 미리보기를 주소 단위로 캐시한다. 2026-10-26 까지는 `og:image` 가 만료된 노션 주소였고, 지금은 사이트 안의 `thumbnail.jpg` 에 `?v=20261026` 꼬리표를 붙여 가리킨다. 사진을 다시 바꾸면 꼬리표 값도 바꿔야 캐시를 피한다.
- 대응: `public/thumbnail.jpg` 교체 → `index.html` 의 `og:image` 꼬리표 값 변경 → 배포. 사진은 1500×1000(`og:image:width`/`height` 와 같은 비율)으로 `sips -Z 1500 <원본> --out public/thumbnail.jpg` 로 만든다. 확인: 새 채팅방에 링크를 붙여 사진이 뜨는지 본다.

## 개발 서버가 안 뜬다

- 증상: `npm run dev` 가 포트 오류로 바로 종료된다.
- 원인: `vite.config.js` 에 `strictPort: true` 와 `port: 5173` 이 고정되어 있어 다른 프로세스가 5173 을 쓰고 있으면 다른 포트로 넘어가지 않고 실패한다. 휴대폰에서 같은 Wi-Fi 로 접속해 보기 위해 `host: true` 로 열어 둔 것으로 보이며, 포트를 못 박은 이유는 기록에 없다.
- 대응: 5173 을 쓰는 프로세스를 끈다(`lsof -i :5173`). 포트를 바꾸면 네이버 콘솔의 등록 URL 도 바꿔야 지도가 뜬다.
