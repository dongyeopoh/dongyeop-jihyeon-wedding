# 0003. 결혼식 이후 사이트 보존, 계좌 섹션 제거와 계좌 데이터 삭제

## 배경

2024-11-02 결혼식이 끝났다. 사이트를 내릴지, 남길지, 남긴다면 무엇을 빼야 할지 정해야 했다. 특히 계좌번호는 식이 끝난 뒤에도 공개 번들에 남아 있을 이유가 없다.

## 결정

- 사이트는 기록용으로 계속 공개한다. 기능 확장은 하지 않고 문구·사진 같은 소소한 수정만 한다.
- 2026-01-28 "마음 전하실 곳" 섹션을 화면에서 뺐다. 2026-10-20 에 한 걸음 더 나가 계좌번호와 송금 링크를 `src/data.json` 에서도 삭제하기로 확정했고, 2026-10-26 에 코드·데이터를 지우고 재배포까지 마쳤다. 양가 부모님 성함은 청첩장의 본문이므로 유지한다.
- 방명록(GitHub 이슈)은 유지한다.
- D-day 는 "지났습니다" 로 경과 시간을 보여주는 현재 동작을 그대로 둔다.

## 검토한 대안

- **사이트를 내리고 저장소만 보관**: 가장 안전하지만 이미 공유된 링크가 전부 죽고 방명록을 다시 볼 수 없게 된다. 기각.
- **화면에서만 숨기고 데이터는 유지(다시 켤 때를 대비)**: 번들에 계좌번호가 그대로 남아 공개되는 상태가 계속된다. 다시 켤 일이 없으므로 기각.
- **다른 사람의 청첩장 템플릿으로 재사용**: 그럴 계획이 없다고 확인했다. 따라서 "데이터만 갈아끼우면 되게" 만드는 추가 작업은 하지 않는다.

## 결과

- 새 기능을 요구하는 작업은 이 결정과 충돌한다. 그런 요청이 오면 먼저 사용자에게 보존 모드를 바꿀지 확인해야 한다.
- 계좌 섹션 코드(`src/layout/Account/`)와 결제 앱 아이콘도 2026-10-26 에 함께 삭제했다.
- main 과 gh-pages 이력을 계좌번호 없는 상태에서 새로 시작했다(2026-10-26). 옛 이력은 저장소 밖 백업 번들에만 있다. GitHub 서버에 남을 수 있는 옛 커밋 객체는 브랜치에서 보이지 않으면 충분하다고 보고 지원팀 삭제 요청은 하지 않았다.
